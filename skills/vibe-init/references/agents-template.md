# AGENTS.md 模板(新项目)

初始化时技术栈未定:依赖技术栈的值以"待补全"写入,不臆造,开发启动后由 agent 实测回填(要求见下表)。`{{COMMIT_POLICY}}` / `{{PUSH_POLICY}}` 来自 SKILL.md 第二步与用户确认的策略。语言用简体中文。本模板即全新项目仓库 `AGENTS.md` 的全部内容(无 fork 层)。

用户选**不发版**时:整段删除「版本与发布」节,并删掉回填表中对应行;其余不变。

## 回填规则(开发启动后执行)

| 待补全处 | 回填要求 |
| -------- | -------- |
| 「项目是什么」 | 用用户描述项目的原话,不改写成技术术语 |
| 「完成定义」验证门命令 | 按"类型检查 + 测试"选命令,逐一实测后回填;构建/打包不算验证门 |
| 「完成定义」运行方式 | 实际启动核实;纯库/CLI 改为"如何调用" |
| 「知识沉淀」依赖安装命令 | 该生态官方命令(如 `uv sync`、`pnpm install`),实测 |
| 「版本与发布」版本号载体 | 确定版本号写在哪个文件哪个字段(`package.json` 的 `version`、`pyproject.toml` 的 `project.version`、`Cargo.toml` 的 `package.version` 或 `VERSION` 文件),实测后回填;多处须一致 |
| `.gitignore` 技术栈条目 | 按生态补齐 |

## 模板正文

````markdown
# Agent 开发约定

本文件是本仓库 AI agent 的工作契约:维护者不写代码、只提需求与验收,实现、验证、文档、提交均由 agent 完成。用户全局规则继续生效,本文件只写项目特有约定,冲突时以本文件为准。

## 项目是什么

待补全:用用户描述项目的原话补全,不改写成技术术语。

## 协作模式

- 用户的话按"需求与验收期望"理解,不是技术指令;技术选型、实现、文件组织由 agent 定。
- 方案不唯一且影响后续走向时,给 2~3 个带取舍的选项让用户选;能安全推断的直接做并说明取舍。
- 不问只有程序员才能答的判断题;必须拍板时一次问清并附默认建议。

## 完成定义(每次交付前核对)

1. 验证门通过:验证门命令**待补全**(技术栈确定后按"类型检查 + 测试"实测回填;回填前以第 2 条为准)。
2. 功能跑通:启动并自测核心路径;有界面或输出变化,附截图或运行结果。
3. 交付说明讲给不写代码的人:做了什么、怎么看到结果、有什么限制;没完成或没把握的直说。

## 前端调试不干扰用户

前端调试一律后台化、非侵入:headless 浏览器、脚本/日志验证、dev server 后台。不自动开窗口、不抢焦点、不改剪贴板、不弹通知、不模拟键鼠;需要可视化先给截图/日志,确需另开浏览器用独立 profile 并先告知。

## 提交与推送

- 仓库既有约定优先。
- {{COMMIT_POLICY}}
- {{PUSH_POLICY}}
- 提交信息用 Conventional Commits;敏感内容不入库,凭据产物先写进 `.gitignore`。

## 版本与发布

- 只在用户明确要发版时改版本号;遵循 SemVer 2.0.0,标签 `vX.Y.Z`。
- 发布闸门:改版本号、建本地 annotated tag 后**停下等用户批准**,批准后才推 tag、建 Release。
- 版本号载体**待补全**(技术栈确定后实测回填);未回填不发布。

## 知识沉淀

- 依赖安装命令**待补全**(技术栈确定后实测回填,并同步 README)。
- 重大技术决策在 `docs/decisions.md` 记一行:日期、决策、为什么、放弃什么。
- README 面向用户维护:项目是什么、怎么启动、怎么用,保持非程序员能看懂。
````
