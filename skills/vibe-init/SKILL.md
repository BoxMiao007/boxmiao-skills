# Vibe Coding 新项目初始化(0 → 1)

从一个空文件夹起步,只做必要的初始化,把"用户只提需求,agent 全权实现、验证、交付"的协作契约立起来。产出:

- 仓库根 `AGENTS.md`:协作模式、完成定义、提交与推送策略、需求登记、知识沉淀;技术栈相关的验证门命令、运行方式、依赖安装命令以"待补全"状态写入,开发启动后由 agent 实测回填
- git 仓库、`.gitignore`(通用条目)
- README:顶部固定带「AI Agent 开发声明」
- 开发启动(技术栈、骨架、需求规划)由其他 skill 或规划模式进行;日常开发按本仓库 `AGENTS.md` 执行

用户不写代码、也不看代码,本 skill 的一切产出以此为设计标准:写进 AGENTS.md 的命令必须实测(初始化时没有就标注待补全,不许臆造),交付必须让用户能自己感知结果。

## 第一步:确认起点(只读)

1. 目录现状:空目录 / 空仓库 / 已有代码。**已有代码时停下**:本 skill 只做从零开始的全新项目,遇到已有代码先向用户确认怎么处理;用户明确要从零重写时,确认理解无误、接受丢弃现有内容后再继续。
2. 用户已经说清要做什么的,把原话记下来备用;没说就不问,留给开发启动时补全。

## 第二步:与用户确认(每项给默认值,用户一句话采纳)

1. **提交策略**(默认):不自动提交——完成并验证后报告,用户说提交才提交(遵循用户全局规则);仅当用户明确要求时,才写入"每个需求验证通过后自动提交"的授权。
2. **推送策略**(默认):不自动推送;用户说"推"才推到 `origin`。

不问技术问题:技术栈、骨架、目录结构都属于开发启动阶段,由后续规划流程决定。

## 第三步:执行

1. `git init`(还不是仓库时),先写 `.gitignore`(`.env`、`*.key`、操作系统杂项;技术栈相关条目待确定后补),保证第一次提交前已就位。
2. 按 `references/agents-template.md` 写 `AGENTS.md`:已确定的信息如实填入;技术相关的验证门命令、运行方式、依赖安装命令保持"待补全"标注。**待补全不等于臆造——回填前必须实际执行核实,没验证过的命令不得写入。**
3. 写 README:顶部按 `references/readme-vibe-declaration.md` 固定写入「AI Agent 开发声明」(块内链接了 AGENTS.md,须在第 2 步之后);正文只写已知信息,未知处标注待补全,保持非程序员能看懂。
4. **不自动提交、不推送**:报告全部变更与关键决策,提交时机按确认过的提交策略和用户全局规则。

## 红线

- 本 skill 不选技术栈、不搭骨架、不做需求规划——那些属于开发启动阶段;技术栈确定后,由当次开发的 agent 实测命令回填 AGENTS.md 和 README 的待补全处。
- 模板不复制用户全局规则(语言、依赖管理、破坏性操作确认等全局已有),只写项目特有约定,必要处引用全局规则。
- 初始化只搭框架和规则;后续一切开发按写好的 AGENTS.md 执行。
