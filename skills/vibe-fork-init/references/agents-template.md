# AGENTS.md 模板——协作层

用真实值替换全部 `{{...}}` 占位符后写入仓库根 `AGENTS.md`;不适用的小节整段删除,不留占位符。语言用简体中文。命令类占位符必须来自 SKILL.md 第一步的收集结果(优先 CI 里实际在跑的命令),不允许臆造;非 CI 来源的按 `命令(待实测:首次运行核实后移除本标注)` 标注。不发布版本的仓库,写入时删除「版本与发布」节。

本仓库可能是 fork 也可能不是:fork 仓库再按 `fork-agents-sections.md` 追加 fork 层(非 fork 到本文件为止),合并策略见 SKILL.md 第二步 6。

## 占位符对照

| 占位符 | 含义 | 来源 |
| ------ | ---- | ---- |
| `{{PROJECT_SUMMARY}}` | 一句话:项目是什么、给谁用 | 项目定位 + 用户要做的开发,不改写成技术术语 |
| `{{VERIFY_COMMANDS}}` | 验证门命令:类型检查 + 测试;构建/打包不算验证门 | 第一步收集的真实命令;CI 来源直接写,其他带"待实测" |
| `{{RUN_COMMAND}}` | 本地运行/启动命令及访问方式 | 从 README/文档提取;纯库/CLI 改为"如何调用" |
| `{{COMMIT_POLICY}}` | 提交策略 | 与用户确认的选项 |
| `{{PUSH_POLICY}}` | 推送策略 | 与用户确认的选项 |

## 模板正文

````markdown
# Agent 开发约定

本文件是本仓库 AI agent 的工作契约:维护者不写代码、只提需求与验收,实现、验证、文档、提交均由 agent 完成。用户全局规则继续生效,本文件只写项目特有约定,冲突时以本文件为准。

## 项目是什么

{{PROJECT_SUMMARY}}

## 协作模式

- 用户的话按"需求与验收期望"理解,不是技术指令;技术选型、实现、文件组织由 agent 定。
- 方案不唯一且影响后续走向时,给 2~3 个带取舍的选项让用户选;能安全推断的直接做并说明取舍。
- 不问只有程序员才能答的判断题;必须拍板时一次问清并附默认建议。

## 完成定义(每次交付前核对)

1. 验证门通过:{{VERIFY_COMMANDS}}
2. 功能跑通:用 {{RUN_COMMAND}} 启动并自测核心路径;有界面或输出变化,附截图或运行结果。
3. 交付说明讲给不写代码的人:做了什么、怎么看到结果、有什么限制;没完成或没把握的直说。

## 前端调试不干扰用户

前端调试一律后台化、非侵入:headless 浏览器、脚本/日志验证、dev server 后台。不自动开窗口、不抢焦点、不改剪贴板、不弹通知、不模拟键鼠;需要可视化先给截图/日志,确需另开浏览器用独立 profile 并先告知。

## 提交与推送

- 仓库既有约定优先。
- {{COMMIT_POLICY}}
- {{PUSH_POLICY}}
- 敏感内容不入库,凭据产物先写进 `.gitignore`。

## 版本与发布

- 版本号沿用本仓库既有编号方式(一般即上游约定),只在用户明确要发版时改。
- 发布闸门:改版本号、建本地 annotated tag 后**停下等用户批准**,批准后才推 tag、建 Release。

## 知识沉淀(保证新会话能接手)

- 重大技术决策在 `docs/decisions.md` 记一行:日期、决策、为什么、放弃什么。
````
